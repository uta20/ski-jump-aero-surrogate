# Ski Jump Aero Surrogate

スキージャンプの飛行を, 揚力・抗力を考慮した2次元質点モデルでシミュレーションし, **物理モデルの理解 → データ生成 → 機械学習(サロゲートモデル・感度分析)** までを一貫して行うプロジェクトです. 卒業研究(富岳を用いた空力CFD)で得た空力値(有効揚力面積・有効抗力面積)を, 軌道計算と飛距離の分析に接続することを目指しています.

| | |
|---|---|
| **現在の状態** | v0.4 の実データとの照合まで実装済み. 照合の結果, シミュレータの**踏切速度への感度が実データより大きい可能性**が見つかった([詳細](#実データとの照合v04)). 非定常CFD(3ケース)の結果は計算待ちのため, **空力値はすべて動作確認用のプレースホルダ**で動かしている. 実データが届いたら, 仮のシナリオをCSVから作ったシナリオに差し替えるだけで, 同じパイプラインが実データで動く |
| **次のマイルストーン** | 速度感度の食い違いの原因の確認(離陸角と速度の関係など), 実データでの設定の確定(`scripts/inspect_cfd.py`), 機械学習(v0.5)と感度分析(v0.6)の実装 |

> **重要**: 現時点のデモで使っている質量・有効揚力面積・有効抗力面積・踏切条件は, すべて動作確認用の代表値です. 実在の選手・用具・CFD結果の値ではなく, 得られる飛距離も実際の競技を再現するものではありません.

---

## 目的とストーリー

1. **物理モデルの理解**: 運動方程式を自分で立て, 解析解(真空中の放物運動, 終端速度など)と突き合わせて実装の正しさを確認する
2. **データ生成**: 踏切速度・踏切角・風・有効面積などを変えながら, 疑似データセットを自作する
3. **機械学習**: 条件 → 飛距離の関係をサロゲートモデルで近似し, 感度分析で「何が飛距離を支配するか」を調べる

### 機械学習の位置づけ(誤解を避けるために)

質点モデルのODEはミリ秒で解けるため, **サロゲートによる計算の高速化そのものは主張しません**. 価値を置くのは次の3点です.

- **感度分析**: シミュレータに対するSobol指数を「正解の感度構造」とし, サロゲート上のSHAPなどがそれを再現できているかを検証する
- **不確実性の伝播**: 空力値の不確かさ(補間誤差, CFDの誤差, 文献値のばらつき)が飛距離のばらつきにどれだけ効くかを定量化する
- **ケース数が限られるCFDの活用**: 少数のCFDケースから, 軌道・飛距離への影響まで一貫して追えるようにする

合成データ上のMAEは, シミュレータに入れたノイズの大きさでほぼ決まるため, 実データを使った論文のMAEとの優劣比較には使いません. 論文の値は, パラメータ範囲やノイズ量を決める際の参考値としてのみ使います.

## 物理モデル

選手+用具を質量 *m* の質点とみなし, 空気に対する相対速度を `v_rel = v − w`(*w* は風速ベクトル)とします.

```
m dv/dt = m g
          − (1/2) ρ A_D |v_rel| v_rel                   (抗力: v_rel と逆向き)
          + (1/2) ρ A_L |v_rel| (−v_rel_y, v_rel_x)     (揚力: v_rel に垂直で上向き側)
```

- **A_D = Cd·S は有効抗力面積, A_L = Cl·S は有効揚力面積** [m²] です. 空力値はこの2つを直接扱い, 基準面積 S の定義は別に持ちません. CFDで得た力を (1/2)ρv² で割れば, そのまま有効面積になります

- 座標系: 原点は踏切点, x は前方が正, y は鉛直上向きが正
- 風は水平成分のみ. +x 向き(追い風)が正, 向かい風は負
- 着地は「位置が斜面の高さを上から下へ横切る瞬間」として, `scipy.integrate.solve_ivp` のイベント検出で求める
- 飛距離は, 踏切点から着地点まで**斜面に沿って測った長さ**

### このモデルの限界

姿勢の変化・選手の回転運動・スキー板と身体の相互作用は扱いません. 空力的な振る舞いはすべて有効面積 A_L, A_D に押し込めています. 文献値を取り込むときは, 有効面積として与えられている値を使います(Cl・Cd だけが示されている文献は, その基準面積 S が分からないと有効面積に換算できません).

### 既知の挙動: 風の効果の向き(要検証)

有効面積が一定のこのモデルでは, **地面に対する踏切速度を同じにして風だけを変えると, 向かい風の方が飛距離が短くなる**という結果になりました(プレースホルダの有効面積での確認. 揚抗比 A_L/A_D = 0.6〜1.4 の範囲で, 約 −8m). 風の符号の実装自体は, 相対速度が同じなら加速度が一致することをテストで確認しています.

| 条件(プレースホルダの有効面積) | 向かい風 (−3 m/s) | 追い風 (+3 m/s) | 差 |
|---|---:|---:|---:|
| 抗力のみ (A_L=0, A_D=0.40 m²) | 83.5 m | 93.3 m | −9.8 m |
| 揚力+抗力 (A_L=0.56 m², A_D=0.40 m²) | 170.2 m | 178.6 m | −8.3 m |

抗力のみなら向かい風が不利になるのは自明で, 揚力を加えても, この代表値の範囲では抗力の効果が上回りました. 一方, 実際の競技では向かい風が有利とされ, FISの風補正点もその前提で設計されています. したがって, **実際のCFD由来の有効面積(迎角や時間に依存する値)を入れたときに, 風の効果の向きを再現できるか**は, シミュレータの妥当性を確かめる重要な検証項目です(ロードマップ v0.4). 再現できない場合は, 有効面積を一定とする仮定や質点近似の限界を示す結果として, そのまま報告します. **`JP_data.csv` には風の列が無いため, 実データでは検証できません**(下の「実データとの照合」を参照).

なお, 揚抗比 A_L/A_D を 2.0 以上にすると(A_D = 0.40 m² の場合)着地しない(`landed=False`)条件が現れますが, これは揚力が過大な非現実的な領域です.

## CFD結果の取り込み(v0.2)

コードに与えるデータは, **空気密度 ρ, 自由流の速さ U, および時刻・抗力 D [N]・揚力 L [N] の時系列**(CSV)と仮定します. 軌道計算には, これを有効面積の時系列に変換して使います.

```
A_D = D / ((1/2) ρ U²),   A_L = L / ((1/2) ρ U²)
```

抗力は自由流方向を正, 揚力は鉛直上向き側を正とした値を与えます. 抗力の平均が負のCSVは, 符号の規約が逆である可能性が高いため読み込み時にエラーにします(揚力は開始直後に負になりうるため, 同様のチェックはしません).

処理は次の順で行います.

1. **読み込み** (`load_drag_lift_csv`): 時間刻みが想定値(1.0E-4 s)と一致するかを検査し, 列の取り違えを検知する
2. **変換** (`to_effective_areas`): 密度と流速は必須の引数で, 既定値はない
3. **初期過渡の処理** (`hold_initial`): 計算開始直後の過渡的な立ち上がりの区間を, その直後の数msの平均値で置き換える. 時間軸(t=0 が踏切)は保つ
4. **平滑化と間引き** (`smooth_and_resample`): 乱流由来の細かい変動を移動平均で除き, 1ms 程度に間引く. **平滑化の幅は, 力積 ∫A dt が保たれることを確認して決める**
5. **物理コアへの接続** (`to_time_table`): 0.5秒より後は `BlendedEffectiveAreas` で文献値になめらかにつなぐ

1〜5を1回で行う入口が `cfd_scenario` です. 実データが届いたら, 仮のシナリオの代わりにこの関数で作ったシナリオを使います.

実データの確認には `scripts/inspect_cfd.py` を使います. 密度・流速などはすべて必須の引数です.

```bash
uv run scripts/inspect_cfd.py data/cfd/case1.csv \
    --header no --rho 1.2 --speed 26 \
    --skip 0.005 --window 0.005 --step 0.001 \
    --plot outputs/case1.png
```

要約(各成分の範囲, 初期過渡の目安, 処理前後の力積)とグラフが出力されます. 上の引数の値は書き方の例であり, 実データの条件に合わせて設定してください.

### 仮定と限界

- CFDは一定方向・一定の速さの流れの中での解ですが, 実際の飛行では相対速度の大きさと向きが変わります. 有効面積 A(t) をそのまま使うことは, 「選手の姿勢が時間とともに同じように変わる」という仮定に相当します
- 3ケース(揚力重視・抗力抑制・バランス型)は連続パラメータではなく離散的なシナリオとして扱い, ケース間の補間はしません
- 2次元モデルなので, 横力は使いません

## データ生成(v0.3)

軌道計算から疑似データセットを作ります(1ジャンプ = 1行). 連続変数をラテン超方格(LHS)でサンプリングし, 飛距離・滞空時間・着地の有無を目的変数として記録します. 同じ`seed`なら同じ結果になります.

| 区分 | 変数 | 内容 |
|---|---|---|
| 観測可能な条件 | `speed`, `angle_deg`, `wind_x`, `rho`, `mass`, `slope_deg`, `scenario` | 踏切条件・環境・斜面・空力シナリオ(3種類から無作為に割り当て) |
| 空力の不確かさ | `cfd_scale`, `late_scale` | CFD区間(0.5秒まで)と文献値区間(以降)の有効面積にそれぞれかかる乗数. **どちらの区間の不確かさが飛距離に効くかを, 感度分析で分けて見るため** |
| 潜在変数 | `athlete_id`, `athlete_lift_factor`, `athlete_drag_factor`, `athlete_speed_offset`, `gust`, `angle_noise` | 疑似選手ごとの個人差と, ジャンプごとのノイズ(突風・踏切角のぶれ). 現実には観測できない量 |
| 目的変数 | `distance`, `flight_time`, `landed` | 斜面沿いの飛距離, 滞空時間, 着地したか |

疑似選手は`n_athletes`人で, 同じ選手は同じ個人差を持ちます. 評価では**選手単位で分割(GroupKFold)**します.

```bash
# 仮の値で動作確認(数値はすべてプレースホルダ. 実行時に警告が出ます)
uv run scripts/generate_dataset.py --n 2000 --seed 0

# 実データ(CFDモード). 仮の値が混ざらないよう, 次の引数がすべて必須です
uv run scripts/generate_dataset.py \
    --cfd lift_oriented=data/cfd/a.csv --cfd balanced=data/cfd/b.csv \
    --cfd drag_suppressed=data/cfd/c.csv \
    --header no --rho 1.2 --speed 26 \
    --skip 0.005 --window 0.005 --step 0.001 \
    --late-lift-area <文献値> --late-drag-area <文献値>
```

出力は`--out`のCSVと, 同じ場所の`*_config.json`(設定)・`*_source.json`(空力シナリオの出所). 出所を残すのは, 仮の値で作ったデータと実データで作ったデータを後から取り違えないためです.

> **重要**: 範囲・ノイズの大きさ・仮のシナリオ・後半の仮の値は**すべてプレースホルダ**で, 出典のある値ではありません. 現時点のデータから物理的な結論は出せません. 仮の値での生成は, 実データが届く前にパイプライン(データ生成 → 機械学習 → 感度分析)を動かして確かめるためのものです.

## 実データとの照合(v0.4)

SkiTBのメタデータ`JP_data.csv`(100ジャンプ)の踏切速度・飛距離・ヒル規模(K点・HS)を使い, シミュレータを照合します. **シミュレータ側の空力値は仮のシナリオ(プレースホルダ)**なので, ここでの比較から物理的な結論は出せません. 実データ側の統計と, 比較の枠組みを確認するのが目的です.

```bash
uv run scripts/validate_against_real.py --jp-data path/to/JP_data.csv
```

`JP_data.csv`はSkiTB公式サイトから取得してください(本リポジトリには含めていません). 主な数値は`outputs/validation_report.json`に保存されます.

### 実データで検証できること・できないこと

| 項目 | 可否 | 理由 |
|---|---|---|
| 踏切速度の現実的な範囲 | できる | `AthleteSpeed`列がある |
| 同じヒル内の飛距離のばらつき | できる | ノイズの大きさの妥当性の確認になる |
| 踏切速度に対する飛距離の感度 | 難しい | ヒル内の速度の幅が狭く, ゲート選択・風・選手の力量が交絡し, データ数も少ない |
| 風の効果の向き | **できない** | 風の列が無い |

### データの偏り

飛距離は, K点を平均して**+12.8 m**超えています(標準偏差10.4 m, K点を下回ったのは100件中4件). 放送映像から作られたデータで, **良いジャンプに偏っており**, 競技全体の分布を代表しません. 実データのばらつきは, 実際より小さめに出ていると考えられます.

### 結果

**踏切速度の範囲(実データの5〜95%, [m/s])**

| ヒル区分 | 件数 | 下限 | 中央値 | 上限 |
|---|---:|---:|---:|---:|
| normal (K 85〜109) | 29 | 22.9 | 23.9 | 24.9 |
| large (K 110〜184) | 58 | 24.1 | 24.9 | 26.1 |
| flying (K 185〜) | 13 | 27.3 | 28.6 | 29.4 |

`DataGenConfig`の既定の`speed`(24.0〜26.5 m/s)は, large区分の範囲にほぼ一致しますが, normal区分とflying区分はカバーしていません.

**同じヒル・同じ性別の中での飛距離のばらつき**

| | 標準偏差 |
|---|---:|
| 実データ(8グループ, 自由度27) | 5.18 m |
| シミュレータ(速度のばらつきを実データ相当の0.37 m/sにした場合) | 5.64 m |

合計のばらつきは桁が合っています. ただし次の項のとおり, **内訳は合っていない可能性があります**.

**踏切速度に対する飛距離の感度 [m per (m/s)]**

| | 値 |
|---|---:|
| 実データ(ヒル×性別内の回帰, n=35) | +0.47 (95%区間 −4.4〜+7.0) |
| シミュレータ(balancedシナリオ) | +11.07 |

シミュレータの値は, 実データの95%区間の外にあります. シミュレータは飛距離のばらつきの大半を踏切速度で説明しますが, 実データにはそのような明確な依存が見えません.

ただし, 交絡(ゲートの選び方・風・選手の力量)と少ないデータのため, **シミュレータが誤っていると断定はできません**. 感度分析(v0.6)の結果を解釈する前に確認すべき項目として扱います. 原因の候補は次のとおりです.

- 実際の選手は, 速度に応じて踏切角や姿勢を変えている(シミュレータは踏切角を速度と独立にサンプリングしている)
- 着地斜面を一定勾配で近似しており, 実際のヒルの形状(K点・HSに応じた斜面)を反映していない
- 仮の空力値が実際と違う(CFDの結果が届いたら再確認する)

**風の効果の向き**

実データに風の列が無いため検証できません. シミュレータでは, 追い風1 m/sあたり飛距離が約+1.1 m(3シナリオとも)で, 実際の競技で向かい風が有利とされることと**符号が逆**です. 前述の「既知の挙動」のとおり, 有効面積を一定とする仮定や質点近似の限界として扱います. 検証には, 風の値が載っているFISの成績表(`JP_data.csv`の`ResultsLink`)などの別のデータが必要です.
